Sobre subir_version.py — cuándo y cómo usarlo:
subir_version.py sirve para publicar una nueva versión en GitHub (actualiza recursos/version.json, crea el tag Git, y normalmente sube el ZIP a las releases). Se ejecuta después de crear el portable, y solo cuando la versión está lista para distribuir a usuarios.
El flujo normal es:
1. Terminas de desarrollar y pruebas que todo funciona.
2. Creas el portable → doble clic en CREAR_PORTABLE.bat. Esto genera dist/epub-tts-accesible-vX.Y.Z.zip.
3. Subes la versión → doble clic en SUBIR_VERSION.bat. Esto:
• Actualiza recursos/version.json con el nuevo número de versión.
• Crea el tag Git correspondiente (v2.0.0, etc.).
• Sube el ZIP a GitHub Releases (si el script está configurado para eso).
4. Los usuarios que tengan la app abierta y la casilla "buscar actualizaciones" marcada recibirán la notificación al arrancar.
No ejecutes SUBIR_VERSION.bat a mitad de desarrollo ni antes de tener el portable probado, porque una vez que el tag está en GitHub, los usuarios ya ven esa versión como disponible.
