2. El motor de PDFs (pdfplumber)
El plan asume que pdfplumber extraerá "texto limpio" que encajará mágicamente en la tubería de normalización del EPUB. Esto es una suposición muy débil.  
Consulta los detalles de la fuente. Abre el panel lateral.
El problema del PDF: A diferencia del EPUB (que es HTML estructurado), el PDF es un mapa de coordenadas vectoriales. pdfplumber extrae el texto, pero arrastrará encabezados de página, números de página, notas al pie e interrupciones de línea duras en mitad de las frases.

Falta en el diseño: Un módulo intermedio de limpieza específico para PDF (un parser de expresiones regulares) que elimine cabeceras, pies de página y junte las líneas rotas antes de enviar el texto al motor común.

El hecho de que tanto Claude como yo te hayamos dirigido hacia SQLite de forma tan tajante no es una coincidencia ni una sugerencia genérica. Para una aplicación de escritorio que maneja colecciones de archivos, un lector de pantalla y motores de audio, JSON es una bomba de tiempo.
Aquí tienes las razones técnicas y de diseño por las cuales SQLite es la única opción viable para la v3.0:
1. Modificaciones quirúrgicas vs. Reescribir el mundo (Eficiencia de disco)
El problema de JSON: Si tienes una biblioteca con 500 libros y cambias de página en la pestaña "Lectura", la app necesita actualizar el campo ultimo_punto_lectura. Para guardar ese único dato en un archivo JSON, Python tiene que cargar todo el archivo en memoria, modificar esa línea, y reescribir el archivo completo de texto en el disco duro. Si cambias de página cada 30 segundos, estás machacando el disco y consumiendo recursos innecesarios.  
Consulta los detalles de la fuente. Abre el panel lateral.
La ventaja de SQLite: SQLite funciona de manera quirúrgica. Cuando cambias de página, se ejecuta una consulta directa que modifica únicamente unos pocos bytes en la fila exacta del libro activo. El resto de la base de datos ni se inmuta. Es instantáneo y eficiente.
2. Integridad de datos y el "Efecto Apagón" (Robustez)
El peligro de JSON: Si la aplicación se cierra inesperadamente por un error en el motor de audio, si Windows se reinicia por una actualización, o si el ordenador se queda sin batería justo en el milisegundo en el que Python está reescribiendo el archivo JSON, el archivo se corrompe por completo y queda vacío. El usuario perdería toda su biblioteca, sus estanterías y sus puntos de lectura de golpe.  
Consulta los detalles de la fuente. Abre el panel lateral.
La seguridad de SQLite: SQLite es un sistema transaccional (ACID). Cuenta con un registro de confirmación (journaling). Si hay un corte de energía o un cuelgue a mitad de una escritura, SQLite descarta la operación incompleta y restaura la base de datos al último estado seguro en el próximo arranque. Es indestructible en entornos de escritorio.
3. Búsquedas y filtros instantáneos sin saturar la memoria
Con JSON: Para buscar todos los libros de un autor específico o filtrar por "Favoritos", Python tiene que leer todo el JSON, convertirlo en un diccionario gigante en la memoria RAM y luego iterar elemento por elemento con bucles for para encontrar las coincidencias. Con colecciones grandes, esto genera retrasos que bloquean el hilo principal de la interfaz de usuario.  
Consulta los detalles de la fuente. Abre el panel lateral.
Con SQLite: Utiliza índices. Si necesitas los libros de la saga de fantasía que estén sin leer, se le pide a la base de datos mediante una consulta estructurada y esta devuelve únicamente los registros que coinciden en una fracción de milisegundo. No cargas datos basura en la RAM.
4. Concurrencia real (Lectura y exportación simultáneas)
El conflicto con JSON: Si estás en la pestaña "Creador de Audiolibros" exportando un libro en segundo plano (lo que actualiza las cuotas o el progreso) y al mismo tiempo estás leyendo otro libro en la pestaña "Lectura", ambos hilos intentarán abrir, modificar y escribir en el mismo archivo JSON a la vez. Esto provocará un error de colisión de archivos (PermissionError) y la app se cerrará.  
Consulta los detalles de la fuente. Abre el panel lateral.
La solución con SQLite: Gestiona los accesos concurrentes de forma nativa. Un hilo puede estar leyendo la configuración de las reglas del diccionario mientras otro hilo independiente escribe el progreso de la exportación del audiolibro sin que ocurra ningún conflicto.  
Consulta los detalles de la fuente. Abre el panel lateral.
En resumen, usar JSON para una biblioteca es tratar a tu aplicación como un script temporal de juguete. Usar SQLite es tratarla como el software robusto y profesional que estás diseñando para la v3.0.

Si te preocupa cómo poner los elementos en la pantalla de forma que sea cómodo para ti y para otros usuarios de lectores de pantalla, podemos diseñar la jerarquía de navegación (el orden de tabulación y los controles) aquí mismo.
Hagamos una prueba con la nueva pestaña "Biblioteca":
Diseño de la Interfaz Accesible: Pestaña "Biblioteca"
Para que NVDA no se vuelva loco y la navegación sea ultra rápida, la estructura visual y de foco no debe tener controles flotantes raros. El diseño estándar y más eficiente para esta pestaña es un flujo vertical de solo tres paradas de tabulación principales:
1.
La Barra de Búsqueda / Filtros (wx.SearchCtrl o wx.TextCtrl): Lo primero que te encuentras al entrar. Escribes el nombre de un libro o autor. Abajo, un par de casillas de verificación opcionales (Filtro por Favoritos, Filtro por No Leídos).
2.
El Árbol de Colecciones (wx.TreeCtrl): A la izquierda (o como control previo). Aquí aparecen tus "Estanterías" o Sagas (ej: Todo, Saga de Ender, Fantasía). Al moverte con las flechas arriba/abajo por el árbol, se filtra automáticamente la lista de libros.  
Consulta los detalles de la fuente. Abre el panel lateral.
3.
La Lista de Libros (wx.ListCtrl en modo reporte): El control principal. Muestra los libros que coinciden con el filtro o la estantería seleccionada.
El flujo del foco con NVDA:
Entras a la Biblioteca con Ctrl + Tab. El foco cae directamente en la lista de libros (o en la barra de búsqueda).
Bajas con las flechas por la lista de libros. NVDA lee: "El Juego de Ender, Pedro Urvi (suposición de metadato), No leído".
Pulsas Enter sobre el libro: La app intercepta la pulsación, lee el ultimo_punto_lectura en SQLite, oculta la pestaña Biblioteca, activa la pestaña Lectura, carga el texto en esa posición y pone el foco en el área de lectura. Todo en un solo paso.
